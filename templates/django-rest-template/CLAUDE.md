# Django REST — Claude Code Instructions

## Stack
- Django 5.2 + Django REST Framework 3.16
- Python 3.12 — strict typing everywhere (`from __future__ import annotations`)
- uv for dependency management (`uv sync`, `uv run`)
- Ruff 0.15 for lint + format
- MyPy 1.14 strict with django-stubs + drf-stubs
- Pytest + pytest-django for testing

## Commands
```bash
uv sync --all-extras                    # install all deps
uv run python src/manage.py runserver   # dev server
uv run pytest                           # run tests
uv run pytest --cov=src -n auto         # tests with parallel coverage
uv run ruff check src tests             # lint
uv run ruff format src tests            # format
uv run mypy src                         # type check
uv run python src/manage.py makemigrations
uv run python src/manage.py migrate
```

## Architecture
- Settings: `src/config/settings/{base,development,production,test}.py`
- Apps live under `src/` — each Django app is a Python package
- URL routing: `src/config/urls.py` → `src/api/urls.py`
- Custom error envelope: `src/api/exceptions.py`
- All models use `BigAutoField` (set in base settings)

## Code Rules
- Always use `from __future__ import annotations` at top of every file
- Type-annotate ALL functions including `self` return types
- Never use `os.environ` directly — use `python-decouple`'s `config()`
- `django.utils.timezone.now()` not `datetime.now()`
- Migrations must be included with model changes — run `makemigrations`
- Use `model-bakery` or `factory-boy` for test fixtures, never raw `Model.objects.create` in tests
- API endpoints must have drf-spectacular `@extend_schema` decorators

## Test Rules
- `DJANGO_SETTINGS_MODULE = config.settings.test` for all tests
- Mark slow tests: `@pytest.mark.slow`
- Use `pytest.mark.django_db` for DB tests
- Coverage threshold: 80%

## Security
- Never log sensitive data (passwords, tokens, PII)
- Always validate input at serializer level
- Use DRF `permission_classes` on every ViewSet

## Commit Rules

Format: `<type>(<scope>): <subject>` — subject max 72 chars, lowercase, no period.

```
feat(api): add user registration endpoint
fix(auth): handle expired token edge case
chore(deps): upgrade Django to 5.2.1
```

**Allowed types:** `feat | fix | docs | style | refactor | perf | test | build | ci | chore | revert`

**Body** (optional): wrap at 100 chars, explain *why* not *what*.

**Footer** (optional): `BREAKING CHANGE: <description>` or `Closes #123`.

### Enforced by commitizen + pre-commit
- Schema pattern: `^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\([a-z0-9-]+\))?: .{3,72}$`
- `no-commit-to-branch` blocks direct commits to `main`

### Forbidden in commit messages
- `Co-Authored-By: Claude` / `Co-Authored-By: Copilot` / any AI agent name
- `Generated by Claude` / `Generated with AI` / `via Claude Code`
- `🤖` emoji or any AI attribution stamp
- `noreply@anthropic.com` or similar AI service emails

These are rejected by the `no-agent-detail` pre-commit pygrep hook (commit-msg stage).

## Additional Best Practices

### Django Patterns
- **Fat models** — business logic in models when simple
- **Service layer** — complex logic in `services.py`
- **Custom managers** — for querysets
- **Signals** — for side effects, but sparingly

### REST API
- **Pagination** — use LimitOffsetPagination or CursorPagination
- **Filtering** — use django-filter
- **Versioning** — URL: `/api/v1/`
- **Caching** — cache with Redis, use cache decorators

### Database
- **select_related** — for ForeignKey/OneToOne
- **prefetch_related** — for ManyToMany/reverse FK
- **only/defer** — fetch only needed fields
- **Indexes** — add for frequently filtered fields

### Performance
- **N+1 prevention** — use select/prefetch_related
- **Database transactions** — use @transaction.atomic
- **Connection pooling** — gunicorn workers + db connections
- **Query counting** — django-queryset-debug

### Testing
- **factory_boy** — for test data
- **pytest fixtures** — for reusable setup
- **Model bakery** — quick object creation
- **APITestCase** — for API tests
