# FastAPI Template — Claude Code Instructions

## Stack
- **FastAPI 0.135+** — async-first, Pydantic v2
- **Python 3.12** — `from __future__ import annotations` in every file
- **SQLAlchemy 2.0 async** + **asyncpg** driver + **Alembic** migrations
- **Pydantic Settings** for config (reads `.env`)
- **structlog** for structured JSON logging
- **uv** for dependency management
- **Ruff 0.15** + **MyPy 1.14 strict** for quality
- **pytest-asyncio** (auto mode) + **httpx AsyncClient** for testing

## Commands
```bash
uv sync --all-extras                          # install all deps
uv run uvicorn app.main:app --reload          # dev server (port 8000)
uv run alembic upgrade head                   # apply migrations
uv run alembic revision --autogenerate -m ""  # generate migration
uv run alembic check                          # verify no pending changes
uv run pytest                                 # run all tests
uv run pytest tests/unit -n auto              # parallel unit tests only
uv run pytest --cov=app --cov-report=term-missing
uv run ruff check src tests alembic           # lint
uv run ruff format src tests alembic          # format
uv run mypy src                               # type check
```

## Architecture — Layered
```
router (src/app/api/v1/*.py)
  └── service (src/app/services/*.py)
        └── repository (src/app/repositories/*.py)
              └── SQLAlchemy model (src/app/models/*.py)
```
- **Routers** — HTTP only: parse request, call service, return response
- **Services** — business logic, orchestration, no HTTP concerns
- **Repositories** — all DB queries, returns domain objects
- **Models** — SQLAlchemy ORM tables only
- **Schemas** — Pydantic request/response models only (separate from ORM models)

## Code Rules
- `from __future__ import annotations` at top of every file
- All async functions must be `async def` — never use sync DB calls
- Config only via `get_settings()` — never `os.environ` directly
- Logging only via `structlog.get_logger(__name__)` — no `print()` or `logging.getLogger()`
- All endpoints must declare `response_model` explicitly
- Error hierarchy: raise `AppError` subclasses, never `HTTPException` directly from services
- ORM models and Pydantic schemas must be **separate classes**
- Always use `text()` with bound params for raw SQL — never f-strings in SQL

## Test Rules
- `asyncio_mode = "auto"` — all test coroutines run automatically
- Use `AsyncClient` from `httpx` for endpoint tests, not `TestClient`
- Override `get_db` dependency in `conftest.py` for transactional rollback
- Unit tests: no DB, no HTTP — test pure logic only
- Integration tests: use `@pytest.mark.integration`
- Coverage threshold: 80%

## Migration Rules
- After every model change: `uv run alembic revision --autogenerate -m "describe change"`
- Review autogenerated migration before committing
- Never modify applied migrations — create a new one
- `uv run alembic check` must pass in CI before merge

## Security Rules
- `SECRET_KEY` has no default — must be in `.env`
- `DEBUG=false` enforced in production by settings validator
- Docs (`/api/docs`) disabled in production
- JWT via `python-jose`, passwords via `passlib[bcrypt]`

## Commit Rules

Format: `<type>(<scope>): <subject>` — subject max 72 chars, lowercase, no period.

```
feat(auth): implement JWT refresh token rotation
fix(db): handle asyncpg connection pool exhaustion
chore(deps): upgrade SQLAlchemy to 2.0.x
```

**Allowed types:** `feat | fix | docs | style | refactor | perf | test | build | ci | chore | revert`

**Body** (optional): wrap at 100 chars, explain *why* not *what*.

**Footer** (optional): `BREAKING CHANGE: <description>` or `Closes #123`.

### Enforced by commitizen + pre-commit
- Schema pattern: `^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\([a-z0-9-]+\))?: .{3,72}$`
- `no-commit-to-branch` blocks direct commits to `main`

### Forbidden in commit messages
- `Co-Authored-By: Claude` / `Co-Authored-By: Copilot` / any AI agent name
- `Generated by Claude` / `Generated with AI` / `via Claude Code`
- `🤖` emoji or any AI attribution stamp
- `noreply@anthropic.com` or similar AI service emails

These are rejected by the `no-agent-detail` pre-commit pygrep hook (commit-msg stage).

## Additional Best Practices

### API Design
- **REST conventions** — `/users`, `/roadmaps`, use proper HTTP methods
- **Pagination** — always paginate list endpoints with `limit` and `offset`
- **Versioning** — use `/api/v1/` prefix
- **Idempotency** — GET, PUT, DELETE should be safe to retry

### Error Handling
- **Consistent format** — always return same error structure
- **AppError hierarchy** — create specific error classes
- **Log context** — include user_id, request_id, correlation
- **Graceful degradation** — user-friendly messages, not internal errors

### Performance
- **Connection pooling** — configure appropriate pool size
- **Async everywhere** — never block in async functions
- **N+1 prevention** — use eager loading in SQLAlchemy
- **Indexing** — add indexes on frequently queried fields

### Caching
- **Redis** — cache expensive operations
- **Tenant isolation** — include tenant in cache keys
- **Stampede protection** — use atomic operations
- **Invalidation** — track cache keys for proper invalidation

### Docker
- **Layer optimization** — combine apt-get commands, cleanup in same layer
- **PYTHONUNBUFFERED=1** — for real-time logging
- **Multi-stage builds** — smaller final image
- **.dockerignore** — exclude unnecessary files

### AI/LLM Integration (if applicable)
- **Maker-Checker** — separate generation from validation
- **Retry with backoff** — exponential backoff for rate limits
- **Prompt files** — store prompts in separate `.txt` files
- **JSON schema** — enforce structured output with Pydantic
- **Cost control** — rate limit AI endpoints, track token usage
