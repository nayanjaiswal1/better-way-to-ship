# Node Package — Claude Code Instructions

## Stack
- TypeScript 5.8 strict, Node 22+
- **tsdown** for building (NOT tsup — it's unmaintained)
- Vitest 4 for testing
- ESLint 9 flat config (`eslint.config.ts`) + Prettier 3
- pnpm 10 — never use `npm` or `yarn`
- Changesets for versioning + release

## Commands
```bash
pnpm install           # install deps
pnpm build             # tsdown (ESM + CJS + .d.ts)
pnpm dev               # tsdown --watch
pnpm test              # vitest run
pnpm test:coverage     # vitest run --coverage
pnpm lint              # eslint
pnpm format            # prettier write
pnpm typecheck         # tsc --noEmit
pnpm changeset         # create a changeset for versioning
```

## Package Outputs
- `dist/index.js` — ESM
- `dist/index.cjs` — CommonJS
- `dist/index.d.ts` — ESM types
- `dist/index.d.cts` — CJS types
All four are required. `exports` map in `package.json` handles routing.

## Code Rules
- `src/index.ts` is the **only** public API surface — export everything from here
- `verbatimModuleSyntax` is ON — use `import type` for type-only imports
- `sideEffects: false` in `package.json` must stay for tree-shaking
- No `console.log` anywhere in `src/` — use a passed-in logger
- All exported functions must be documented with JSDoc
- `exactOptionalPropertyTypes` is ON — don't assign `undefined` to optional props

## Test Rules
- Coverage: 90% lines/functions/statements, 85% branches
- Test file mirrors source: `src/utils.ts` → `tests/utils.test.ts`

## Release Process (Changesets)
1. `pnpm changeset` — describe the change (patch/minor/major)
2. Commit the generated `.changeset/*.md` file
3. Push to `main` → CI creates Release PR automatically
4. Merge Release PR → CI publishes to npm with provenance

## Commit Rules

Format: `<type>(<scope>): <subject>` — subject max 72 chars, lowercase, no period.

```
feat(parser): support nested object types
fix(exports): correct CJS interop for default export
docs(api): add JSDoc examples for all public functions
```

**Allowed types:** `feat | fix | docs | style | refactor | perf | test | build | ci | chore | revert`

**Body** (optional): wrap at 100 chars, explain *why* not *what*.

**Footer** (optional): `BREAKING CHANGE: <description>` or `Closes #123`.

### Enforced by commitlint + husky
- Subject must be ≥ 3 chars and ≤ 72 chars
- Type must be from the allowed list above
- Scope must be lowercase alphanumeric + hyphens only

### Forbidden in commit messages
- `Co-Authored-By: Claude` / `Co-Authored-By: Copilot` / any AI agent name
- `Generated by Claude` / `Generated with AI` / `via Claude Code`
- `🤖` emoji or any AI attribution stamp
- `noreply@anthropic.com` or similar AI service emails

These are stripped by the husky `commit-msg` hook and rejected by the `no-agent-detail` commitlint rule.

## Do Not
- Do not use `tsup` — project uses `tsdown`
- Do not use `.eslintrc.*` — project uses flat config
- Do not use `require()` in `src/`
- Do not publish manually — use Changesets

## Additional Best Practices

### Library Design
- **Single entry point** — export everything from index.ts
- **Barrel files** — clean exports structure
- **Deep imports** — avoid, use main export
- **Types first** — export types alongside functions

### Error Handling
- **Custom errors** — extend Error class
- **Error codes** — consistent error format
- **Validation** — Zod for input validation

### Performance
- **Lazy initialization** — don't compute on import
- **Tree shaking** — keep ESM clean
- **Bundle size** — monitor with rollup-plugin-visualizer

### Testing
- **Unit tests** — pure functions, no I/O
- **Integration tests** — with actual dependencies
- **Mocking** — use Vitest mock utilities

### TypeScript
- **Strict mode** — always on
- **No any** — use unknown + narrow
- **Generics** — for reusable code
